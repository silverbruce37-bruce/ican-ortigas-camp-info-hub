## 🎯 최적화 전략

### 전략 1: 계층적 로딩 (추천)

```
Level 1: 핵심 (항상 메모리)
├── core/COVENANT.md (4.4 KB)
├── AGENTS.md (요약본, 2 KB)
└── skills/*/README.md (핵심 프로토콜, 5 KB)
총: ~12 KB (1,500 tokens)

Level 2: 작업별 (필요 시 로딩)
├── skills/execution/README.md (TDD 시)
├── skills/collaboration/README.md (협업 시)
└── memory/PROTOCOLS.md (기록 시)
총: ~30 KB (4,000 tokens)

Level 3: 참조 (드물게 사용)
├── VISION_MANIFESTO.md
├── DEVELOPMENT_SUMMARY.md
└── STRUCTURE_DIAGRAM.md
총: ~122 KB (15,000 tokens)
```

---

### 전략 2: 청크 분할

```
각 파일을 의미 단위 청크로 분할:

COVENANT.md → 10 개 청크 (계명별)
skills/README.md → 5 개 청크 (스킬별)
AGENTS.md → 13 개 청크 (에이전트별)

장점:
- 필요한 청크만 로딩
- 평균 500 tokens/청크
- 빠른 검색 및 접근
```

---

### 전략 3: 임베딩 기반 검색 (RAG)

```
1. 모든 문서를 임베딩하여 벡터 DB 에 저장
2. 사용자 요청 시 관련 청크만 검색
3. 검색된 청크만 컨텍스트에 추가

예시:
사용자: "TDD 어떻게 해?"
→ 검색: skills/execution/README.md 의 TDD 섹션
→ 로딩: ~500 tokens (전체 6 KB 대신)
```

**성능 비교**:
```
전체 로딩:    50,000 tokens → 15 초
RAG 검색:     500 tokens → 0.5 초
속도 향상:    30 배
```

---

### 전략 4: 캐싱

```
자주 사용하는 문서 메모리 캐싱:

- COVENANT.md: 90% 히트율

효과: 평균 로딩 시간 60% 감소
```
